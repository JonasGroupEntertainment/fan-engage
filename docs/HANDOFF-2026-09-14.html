Current state

What is built and running

Fan Engage Pro is the super-fan membership app for artists. Fans join an artist community, earn points and tiers, claim Founding Fan status, get SMS and push alerts, and receive a weekly digest. It is a separate product from Brand Engage Pro, which serves businesses.

Stack

  • Next.js 16, React 19, Supabase with row level security, Vercel.
  • Stripe for paid tiers. Mailchimp audience 554139 for email, with DIGESTHTML and DIGESTTEXT merge fields fed by the weekly-digest cron. Twilio for SMS. Web Push with VAPID keys. OpenAI plus pgvector for search and recommendations.
  • Cloudflare Turnstile on signup, password login, and magic link, all fail-closed.

Communities

  • RaeLynn is the launch community. Fans auto-join RaeLynn on onboard.
  • Danger Twins, Dan Marshall, and Hunter Hawkins exist but non-RaeLynn and family artists were paused by migrations on 2026-08-01.
  • Nellie's Southern Kitchen is not here. It belongs to Brand Engage Pro.

Launch hardening, August 2026

  • Shared authentication rate limiter across all auth endpoints.
  • Turnstile token bound to signup and password login. Magic link and forgot-password are hidden in production.
  • Password-first signup. First 100 fans get Founding Fan free.
  • Anon EXECUTE revoked on all SECURITY DEFINER RPCs.
  • Financial and leaderboard tables secured (0049).
  • Last change: duplicate-email signup no longer tells the fan to complete Turnstile.

Workflow

How to make a change safely

Critical rules

Stop at git commit. Never run git push on this repo. Kevin pushes. This is COLLABORATING.md section 9 and it is not negotiable.

Before any SQL, confirm you are in the Fan Engage project and not Brand Engage. The Supabase project switcher defaults to the wrong one.

Do not touch the eighteen network_* migrations without asking. They may belong to JG Advisors infrastructure, not this app.

  1. Fetch upstream and start from upstream main, not the local main, which is about twenty commits behind.
  2. Create a branch named for the fix, for example fix/short-description.
  3. Schema change: new timestamp-named file in supabase/migrations. Apply it to the Fan Engage project by hand and confirm with a select.
  4. Run the launch readiness quality gate before committing. It was added in PR #39 and fails the build on lint or type errors.
  5. Commit with a conventional message and stop. Tell Kevin the branch name and what to push.
  6. After Kevin pushes and Vercel deploys, smoke test on www.fanengagepro.com: signup with a fresh email, Turnstile passes, fan lands in RaeLynn, sign-out works.

Conventions

House rules for this codebase

  • Env var names only: NEXT_PUBLIC_SUPABASE_URL, NEXT_PUBLIC_SUPABASE_ANON_KEY, SUPABASE_SERVICE_ROLE_KEY, STRIPE_SECRET_KEY, STRIPE_WEBHOOK_SECRET, MAILCHIMP_API_KEY, TWILIO_ACCOUNT_SID, TWILIO_AUTH_TOKEN, TURNSTILE_SECRET_KEY, OPENAI_API_KEY, CRON_SECRET. Values stay in Vercel.
  • Production magic links must land on www.fanengagepro.com. The redirect allow list in Supabase must include it.
  • Every new RPC that is SECURITY DEFINER gets anon EXECUTE revoked in the same migration.
  • LAUNCH_CHECKLIST.md is the migration ledger. Update it when you add a file.

Guardrails

Who can do what

  • KevinOnly person who pushes to GitHub and flips production Supabase settings.
  • AgentsBranch, commit, and report. No push, no production SQL without confirming the project first.
  • Artist contentNothing about an artist goes live without that artist's day-to-day manager clearing it. See docs/ARTIST_AGREEMENT_RIGHTS.md.
  • Fan dataPhone numbers and emails never leave Supabase, Mailchimp, or Twilio. No exports to chat or local files.
