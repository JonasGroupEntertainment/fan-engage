What the audit found

  • 34 app inserts go into the 13 tables; 25 did not set community_id. That is why 0099 uses a trigger: dropping the default alone would have broken those writes.
  • 5 database functions insert into those tables. Only upsert_notification left the community out.

How to test a migration without touching production

Homebrew has Postgres 18 at /opt/homebrew/opt/postgresql@18/bin. Start a scratch cluster with initdb and pg_ctl, set LC_ALL=en_US.UTF-8 (without it the server exits with "postmaster became multithreaded during startup"), listen on a local TCP port with unix_socket_directories='' (a long data path makes the socket path too long), create stub tables with only the columns involved, apply the migration twice, run the cases, run the rollback, then stop the server and delete the directory.
