Workflow

How changes land

Read this before pushing

Kevin authorized pushing, opening, and merging PRs in chat for this session only. Get that go-ahead again each session. Never turn on auto-merge.

Main is protected: a pull request is required, admins are included, the branch must be up to date, and three checks must pass: Unit tests + typecheck, Detect secrets (gitleaks), and Vercel. When a PR is behind main, run gh pr update-branch N and wait for checks again.

cd ~/Developer/fan-engage && git checkout main && git pull
git checkout -b fix/short-description
# make the change, run npm test in frontend/, commit with a conventional message
git push -u origin fix/short-description
gh pr create --base main --head fix/short-description --title "..." --body "..."
gh pr checks N --watch --fail-fast
gh pr update-branch N          # only if the PR is behind main, then watch checks again
gh pr merge N --merge --delete-branch
git checkout main && git pull

The recipe for checking the Production deploy by SHA is in the 2026-09-17 handoff and still works. In this shell, a foreground sleep is blocked; use --watch or an until-loop instead.

Database changes

  1. Apply the SQL to the correct project through the Supabase MCP first, and confirm with a select.
  2. Record it as the next numbered file (0074 next) in root supabase/migrations/ with the header line "Already applied to production via MCP on YYYY-MM-DD; kept here for the repo record."
  3. Any new SECURITY DEFINER function starts closed. Revoke EXECUTE from PUBLIC, anon, and authenticated, grant service_role, and only grant a browser role back with a written reason, the way 0062 does.

Conventions

House rules

  • Every phone number write goes through frontend/lib/phone.ts and is stored as E.164.
  • An SMS opt-in means two fields: fans.sms_opted_in and notification_preferences.sms_enabled. Any new opt-in path must set both.
  • New cron routes need an entry in frontend/vercel.json, or they never run.
  • Env var names only, never values: NEXT_PUBLIC_SUPABASE_URL, NEXT_PUBLIC_SUPABASE_ANON_KEY, SUPABASE_SERVICE_ROLE_KEY, FAD_SUPABASE_URL, FAD_SUPABASE_SERVICE_ROLE_KEY, STRIPE_SECRET_KEY, STRIPE_WEBHOOK_SECRET, MAILCHIMP_API_KEY, TWILIO_ACCOUNT_SID, TWILIO_AUTH_TOKEN, TURNSTILE_SECRET_KEY, OPENAI_API_KEY, CRON_SECRET.
  • Jev runs in shadow mode for non-trivial work. Report its action and reason in one line, then use judgment.
  • Plain English in every report to Kevin, no em dashes, direct truth about what was and was not verified.

Guardrails

Who can do what

  • KevinAdds secret env var values in Vercel, flips production Supabase settings, and gives the per-session go-ahead to land pull requests.
  • AgentsBranch, test, open the pull request, wait for checks, merge only with Kevin's go-ahead, verify the deploy, and report. Never type a secret value anywhere, never print a token, never decrypt an env value.
  • DatabaseConfirm the project ref before every query. Fan Engage, Super Fan Radar, and Brand Engage Pro are three different projects.
  • Fan dataPhone numbers and emails never leave Supabase, Mailchimp, or Twilio. No exports to chat or local files.
  • Other productBrand Engage Pro is for businesses. This app is for artist super fans. Never mix the two.
